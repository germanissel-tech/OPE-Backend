# tests/ — las pruebas, en dos proyectos

Vitest con dos proyectos (`vitest.config.ts`): **`fast`** es la suite por la que se juzga un
cambio —unitarias, integración con `fastify.inject`, reglas del contrato, gobernanza,
arquitectura— y corre en `npm test` en minutos; **`tools`** son las pocas suites que ejecutan
cadenas enteras (la auditoría sobre fixtures, la cadena de calidad, la documentación, el
inventario de README) y corren en `npm run test:tools`; `npm run test:all` corre ambos, como CI;
`npm run test:scoped` elige según lo que cambió. Un directorio `fixtures/` dentro de una suite
es entrada, nunca prueba (`NOT_SUITES`). Las pruebas de tipos (`*.test-d.ts`) las corre
`typecheck`. Las pruebas de aislamiento entre merchants viven con la integración de cada feature.
