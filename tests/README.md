# tests/ — las pruebas, en dos proyectos

Vitest con dos proyectos (`vitest.config.ts`): **`fast`** es la suite por la que se juzga un
cambio —unitarias, integración con `fastify.inject`, reglas del contrato, gobernanza,
arquitectura— y corre en `npm test` en minutos; **`tools`** son las pocas suites que ejecutan
cadenas enteras (la auditoría sobre fixtures, la cadena de calidad, la documentación, el
inventario de README) y corren en `npm run test:tools`; `npm run test:all` corre ambos, como CI;
`npm run test:scoped` elige según lo que cambió. Un directorio `fixtures/` dentro de una suite
es entrada, nunca prueba (`NOT_SUITES`). Las pruebas de tipos (`*.test-d.ts`) las corre
`typecheck`. Las pruebas de aislamiento entre merchants viven con la integración de cada feature.

| `contract/`       | Pruebas de contrato generadas por Schemathesis contra el servidor real (`npm run test:contract`); su README explica el arranque y el merchant de prueba.                                    | fuente            | `test:contract`                                 | —                                                | ninguno (comando propio) |
| `contract-diff/`  | `contract:diff` sobre fixtures: qué es incompatible, qué acepta `x-stability: building`.                                                                                                    | fuente            | `npm test`                                      | —                                                | `fast`                   |
| `contract-rules/` | Un fixture por regla `ope-*` de Spectral y por assertion de Redocly; `gen-fixtures.mjs` los genera; su README explica cómo agregar una regla.                                               | fuente            | `npm test`                                      | "hay un fixture por cada regla"                  | `fast`                   |
| `docs/`           | README con inventario en cada directorio de primer nivel y cabeceras de generados, parches y scripts (ADR-032).                                                                             | fuente            | `npm run test:tools`                            | —                                                | `tools`                  |
| `format/`         | Prettier como único formateador: lo ignorado y lo canónico.                                                                                                                                 | fuente            | `npm test`                                      | —                                                | `fast`                   |
| `governance/`     | Cada `check:*` sobre fixtures (ADR, glosario, marcadores, identificadores, idioma, mapa, invariantes, duplicación, código muerto, mutación, `test:scoped`) y la cadena `quality`.           | fuente            | `npm test` (`quality.test.ts` en `tools`)       | —                                                | ambos                    |

| `integration/`    | El servidor real en memoria por `fastify.inject`: cada operación del contrato, aislamiento entre merchants, degradación del ledger.                                                         | fuente            | `npm test`                                      | `[invariant:<slug>]` por `check:invariant-tests` | `fast`                   |

| `types/`          | Pruebas de tipos (`*.test-d.ts`): `Result`, claims, condiciones, handlers del servidor, cliente.                                                                                            | fuente            | `npm run typecheck`                             | —                                                | typecheck                |
| `unit/`           | Unitarias por anillo y módulo (`domain/`, `application/`, `interface-adapters/`, `infrastructure/`, `composition/`), más las de los generadores del contrato.                               | fuente            | `npm test` (`contract-docs.test.ts` en `tools`) | mutación en CI                                   | ambos                    |
