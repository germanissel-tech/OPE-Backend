- [x] T032 [US3] Asegurar que el fallo llega a HTTP como `503 store-unavailable` por el camino que

- [x] T033 [P] [US3] Prueba de integración: crear un merchant con el registro caído ⇒ `503` **y el

- [x] T034 [P] [US3] Prueba de integración: rotar una credencial con el registro caído ⇒ `503` **y

- [x] T037 [US3] Verificar que la segunda aserción de T033–T035 (el estado no cambió) **falla** con

## Implementation Strategy

### MVP

F1 → F2 → F3 (US1). Con eso la elección ya no se toma a mano y el comportamiento es idéntico: es
entregable y demostrable solo.

### Incremental

1. F2 → el contrato dice qué se audita y el compilador lo lee.
2. - US1 → nadie elige. **Validar y parar acá si hace falta.**
3. - US2 → olvidarse no compila.
4. - US3 → una acción sin auditar no ocurre.
5. - US4 → el kernel no nombra códigos ajenos.
6. F7 → se retira lo que quedó sin consumidores y se documenta.

### Commits

Uno por historia, en español (restricción del dueño). Dentro de US1 la conversión de los nueve
módulos puede ir junta: es un solo cambio conceptual.
