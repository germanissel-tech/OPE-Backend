# Quickstart — Feature 013: outcomes

Guía de validación: cómo comprobar que una orden entra como venta verificada, se atribuye
sólo por el mecanismo A, es idempotente, se corrobora desde el navegador, se devuelve y
llega firmada. Detalles en [spec.md](spec.md), [data-model.md](data-model.md) y
[contracts/](contracts/).

## Prerrequisitos

- `npm ci` (sin dependencias nuevas), `npm run contract:bundle`.
- Documentos del MVP en `../` (01 §5, §6, §10.3; 02 §5).

## Escenario manual (`npm run dev` + curl)

El merchant de desarrollo lleva `platformSecrets: ["ope_dev_platform_secret"]`;
`node scripts/sign-platform-request.mjs <secret> <archivo-json>` imprime los dos headers de
firma para pegar en curl o Insomnia ([contracts/platform-signature.md](contracts/platform-signature.md)).

1. `POST /v1/events` con señales fuertes de `price` (sesión S, visitante V) → `INTERVENE` con
   `incentive { percent: 5 }`.
2. `POST /v1/orders/corroborations` `{ orderId: "A-1", sessionId: S, visitorId: V, confirmedAt }`
   (ingestKey) → `202`.
3. `POST /v1/orders` firmado `{ orderId: "A-1", total: { amount: "95.00", currency: "ARS" },
items: [{ sku: "SKU-1", quantity: 1 }], confirmedAt, sessionId: S, incentive: { kind: "percent",
value: 5 } }` → `201 { status: "ATTRIBUTED_ORDER" }`.
4. Repetir el paso 3 → `200`; cambiar `total` → `409 idempotency-conflict`.
5. Mismo cuerpo sin firma → `401 signature-missing`; con `X-OPE-Timestamp` de hace 10 minutos
   → `401 signature-expired`.
6. `POST /v1/returns` firmado `{ orderId: "A-1", returnedAt }` → `201 { status: "RETURNED",
orderStatus: "ATTRIBUTED_ORDER" }`; `{ orderId: "Z-9", returnedAt }` → `422 order-unknown`.
7. `POST /v1/orders` con `orderId: "A-2"` sin `sessionId` → `201 { status: "PENDING_CORRELATION" }`.
